# 窗口

打开程序就是一个桌面窗口，不提供网址，也不要求用户自己打开浏览器。画面有两屏。这一份说明窗口行为，不规定颜色和字体。

## 项目列表

列出 `projects/` 下已有的 slug，并可以新建。新建时填写题目和 `kind`（summary=总结、report=报告、paper=论文），写入 `brief.md`，并建立空的 `meta.json`。

打开某个项目时，用该 slug 作为 `thread_id` 读取 `checkpoints.sqlite`。若线程停在中断，直接进入写作主窗并画出当时的确认卡。

## 写作主窗

左栏是对话，输入框可以随消息附上文件：

- `.docx` 存成该项目的 `template.docx`，作为格式标准。
- 其他本地文档存成待确认材料，进入文献确认卡，`content_source` 为 `user_file`。

用户发送一句话后，窗口让图跑一轮。图停在 `interrupt` 时，左栏出现确认卡，不把 diff 或文献列表糊进正文。

右栏读磁盘：

- 大纲
- 每节状态
- 已确认文献数量，以及每条依据是全文、摘要还是用户文件
- 当前 `cursor` 那一节的正文

节草稿落盘后，右栏状态变为 `draft`。接受之前不标成已完成。

用户在右栏点某一节后，输入框下方显示「📍 正在修订: {section.title}」。再次点击其他节会切换修订目标。输入意见后，这一轮的动作是 `revise_section`，只改那一节。右栏和 `export.docx` 一起更新。

输入框支持快捷语法：「改第 3 节:…」会自动解析节名，不需要先点击。

主窗有「导出 Word」。点击后重新合成 `export.docx`，并显示该文件的路径。大纲确认、文献摘录落盘、节草稿或修订之后也会自动合成。

## 确认卡

三种卡，按钮都包含同意和拒绝。大纲和 skill 还可以改完再同意。

| 卡 | 展示 | 同意之后 |
| --- | --- | --- |
| 大纲 | diff | 写 `outline.md`，更新 `meta.json` |
| 文献 | 找到的文献（可能少于 8 条），每条有标题、作者、年份、出处、链接，可勾选。若某条既无开放获取全文也无摘要，标注「无可用文本」 | 勾选为 `accepted`，未勾选为 `rejected`，然后抓取摘录。若结果少于 3 条，建议用户修改检索词 |
| skill | 即将写入的 `SKILL.md` 全文 | 写入 `skills_user/<name>/SKILL.md` |

确认卡上的文献条目比模型提示里的短卡片更全：标题、作者、年份、出处和链接都给用户看。抓取完成后，右栏标明每一条的依据是全文、摘要还是用户文件。关窗再打开时，若还停在勾选，同一张卡用同一份 payload 再画出来。

提问也走左栏，不另开终端。用户的回答作为 `Command(resume=...)` 送回。

## 画像与 skill 列表

主窗展示 `user_profile.md`。每条偏好可以删除。删除立即写回文件，不经过模型。

主窗列出 `skills_user/` 里已有的 skill 名称和 description。可以：
- 点击「删除」按钮，弹出二次确认后删除文件
- 点击 description 进入编辑模式，保存时直接写回文件（不经过模型）
- 修改正文仍通过对话里的 `propose_skill` 确认卡

## 关窗

关窗即退出进程。文稿目录、画像、skill 和检查点都已经在磁盘上。再打开同一项目，停在同一次确认，或停在上一次已经落盘的文稿状态。
